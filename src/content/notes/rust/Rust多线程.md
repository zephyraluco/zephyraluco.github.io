## 线程安全

### 如何保证？

rust使用`Sync`和`Send`来标记数据在线程中传递的安全性:

- 如果类型`T`实现了`Send`，则将类型`T`的**值传递**给另一个线程不会导致数据争用(data rases)或其他不安全性,用于**参数传递**;
- 如果类型`T`实现了`Sync`，则将类型`T`的**引用`＆T`传递**到另一个线程中不会导致数据争用或其他不安全性（`T: Sync`暗含着`＆T: Send`）,用于**参数共享**;

## 多线程通信

### 通道

> 通道是一种线程间安全的消息传递机制。Rust 的标准库提供了 `std::sync::mpsc` 模块，其中包含了同步通道（`sync_channel`）和异步通道（`channel`）的实现。通过发送端（Sender）和接收端（Receiver）可以在不同线程之间传递消息。

#### sync_channel和channel的区别

- `sync_channel`：`sync_channel` 是一个同步通道，它具有固定的缓冲区大小。它使用了`std::sync::mpsc` 模块中的 `SyncSender` 和 `Receiver` 来进行消息传递。`SyncSender` 和 `Receiver` 是线程安全的，可以在不同线程之间发送和接收消息。`sync_channel` 的特点是当通道已满时，发送操作会阻塞当前线程，直到有空间可用；当通道为空时，接收操作会阻塞当前线程，直到有消息可用。

```rust
use std::sync::mpsc;

fn main() {
// 缓冲区大小为10
    let (sender, receiver) = mpsc::sync_channel(10);

    // 发送端发送消息到通道
    sender.send("Hello").unwrap();

    // 接收端从通道接收消息
    let message = receiver.recv().unwrap();
    println!("{}", message);
}
```

- `channel`：`channel` 是一个异步通道，它没有固定的缓冲区大小。它同样使用了`std::sync::mpsc` 模块中的 `Sender` 和 `Receiver` 来进行消息传递。`Sender` 和 `Receiver` 也是线程安全的，可以在不同线程之间发送和接收消息。`channel` 的特点是当通道已满时，发送操作会立即返回一个错误；当通道为空时，接收操作会阻塞当前线程，直到有消息可用。

```rust
use std::sync::mpsc;

fn main() {
    let (sender, receiver) = mpsc::channel();

    // 发送端发送消息到通道
    sender.send("Hello").unwrap();

    // 接收端从通道接收消息
    let message = receiver.recv().unwrap();
    println!("{}", message);
}
```

## 原子类型(atomic)

| 类型                                        | 描述                                                                                    |
| ------------------------------------------- | --------------------------------------------------------------------------------------- |
| `AtomicBool`                                | 原子布尔值（true / false）                                                              |
| `AtomicIsize` / `AtomicUsize`               | 与平台字长相同的有符号/无符号整数                                                       |
| `AtomicI8` / `AtomicU8` / `AtomicI16` / ... | 各种位宽整数                                                                            |
| `AtomicPtr<T>`                              | 原子指针                                                                                |
| `Atomic*` 系列                              | 所有类型都实现了基本的原子操作，如 `load`, `store`, `swap`, `fetch_add`, `fetch_sub` 等 |

## 内存序

内存序是用来管理**多核处理器**或**多线程环境**中，不同线程对**共享内存**的读写操作可见性（Visibility）和执行顺序（Order）的规则和机制。  
在没有内存序限制的情况下，处理器、编译器或操作系统可能会出于性能优化的目的，对代码中指定的内存访问顺序进行**重排序**（Reordering）。

### 为什么需要内存序？

- **编译器重排序：** 编译器为了生成更优化的机器码，可能会改变指令的顺序，只要在**单线程**看来结果不变。
- **处理器重排序：** 现代处理器为了提高效率（例如，利用乱序执行、写缓冲器），实际执行内存操作的顺序可能与程序指定的顺序不同。
- **缓存不一致：** 每个处理器核心通常有自己的**本地缓存**（L1/L2 Cache）。当一个核心修改了共享变量的值时，这个修改可能只在其本地缓存中，而其他核心看不到最新的值。  
  **内存序的作用**：提供一个机制（通常是**内存屏障**指令），来**限制**或**禁止**这种重排序和缓存同步的延迟，从而确保**可见性 (Visibility)**和**有序性 (Ordering)**

### 六种内存序

| **内存序**                            | **类别** | **描述**                                                |
| ------------------------------------- | -------- | ------------------------------------------------------- |
| **Relaxed** (`Release`)               | 最弱     | **只保证原子性**。不提供任何同步或排序保证。            |
| **Acquire** (`Acquire`)               | 获取     | **读操作**。确保它之后的内存访问不会被重排序到它之前。  |
| **Release** (`Release`)               | 释放     | **写操作**。确保它之前的内存访问不会被重排序到它之后。  |
| **AcqRel** (`Acquire-Release`)        | 组合     | **读写操作**。结合了 `Acquire` 和 `Release` 的保证。    |
| **SeqCst** (`Sequential Consistency`) | 最强     | **顺序一致性**。最直观、最安全的，但通常开销最大。      |
| **Consume** (`Consume`)               | 废弃     | **消费者**。比 `Acquire` 弱，但实际使用复杂，已被弃用。 |

**1. `Relaxed` (松散序)**

- **保证：** **仅保证操作的原子性**。
- **重排序限制：** **无**。编译器和处理器可以随意重排 `Relaxed` 操作之前和之后的其他内存操作，前提是不改变本线程的执行结果。
- **用途：** 仅用于简单的原子计数器或统计，当操作的顺序对程序的逻辑结果不重要时。

**2. `Acquire` (获取序) - 用于读取操作**

- **保证：** **获取语义**。
- **重排序限制：** 保证**此 `Acquire` 读操作之后**的**所有**内存操作，都**不会**被重排到它的**前面**。
- **同步作用：** 通常与一个远程线程的 `Release` 操作配对使用，以建立一个**同步屏障**。当线程 B 执行 `Acquire` 读操作成功后，它能保证看到**线程 A 在执行 `Release` 写操作之前**对共享变量所做的所有修改。

**3. `Release` (释放序) - 用于写入操作**

- **保证：** **释放语义**。
- **重排序限制：** 保证**此 `Release` 写操作之前**的**所有**内存操作，都**不会**被重排到它的**后面**。
- **同步作用：** 通常与一个远程线程的 `Acquire` 操作配对使用。当线程 A 执行 `Release` 写操作时，它能保证它**之前**对共享变量所做的所有修改，都会随着这次 `Release` 写操作一起对其他核心**可见**。

**4. `AcqRel` (获取-释放序) - 用于读改写操作**

- **保证：** **同时具备 `Acquire` 和 `Release` 语义**。
- **重排序限制：** 保证**它之前**的内存操作不会被重排到**它之后**（`Release` 语义），同时保证**它之后**的内存操作不会被重排到**它之前**（`Acquire` 语义）。

**5. `SeqCst` (顺序一致性)**

- **保证：** **原子性、AcqRel 保证，以及全局统一的顺序**。
- **重排序限制：** **最强**。它不仅提供了 `AcqRel` 的本地屏障（防止操作跨越自身重排），还提供了**全局同步屏障**。
- **特点：** 保证所有使用了 `SeqCst` 的原子操作，在所有线程看来，都将以**相同**且**唯一**的全局总顺序执行。这是最容易推理的，因为它可以避免一些复杂的并发异常。
- **代价：** 通常比其他内存序（尤其是 `Acquire`/`Release`）带来更高的**性能开销**，因为它可能需要更强的底层同步指令。
