## Box常用函数
- `Box::new(value)`：创建一个`Box`指针，将`value`放入堆中。
- `Box::into_raw(box_ptr)`：将`Box`指针转换为裸指针，不再由`Box`管理内存。
- `Box::from_raw(raw_ptr)`：将裸指针转换回`Box`指针，接管对应的内存。
- `Box::leak(box_ptr)`：将`Box`指针转换为裸指针，但不释放内存，可以安全地传递给其他函数或线程。
- `Box::downcast(box_ptr)`：尝试将`Box`指针转换为具体类型的指针，用于动态类型转换。

## Deref解引用
当我们对智能指针 `Box` 进行解引用时，实际上 Rust 为我们调用了以下方法：
```rust
*(y.deref()) //`deref` 返回一个常规引用，再被 `*` 进行解引用
```
### Deref的实现:
```rust
pub trait Deref {
    // 取消引用后的结果类型
    #[stable(feature = "rust1", since = "1.0.0")]
    #[rustc_diagnostic_item = "deref_target"]
    #[lang = "deref_target"]
    type Target: ?Sized;
    /// Dereferences the value.
    #[must_use]
    #[stable(feature = "rust1", since = "1.0.0")]
    #[rustc_diagnostic_item = "deref_method"]
    fn deref(&self) -> &Self::Target;
}
```
若一个类型实现了 `Deref` 特征，那它的引用在传给函数或方法时，会根据参数签名来决定是否进行隐式的 `Deref` 转换,例如:
```rust
fn main() {
    let s = String::from("hello world");
    display(&s) // 从&String转为&str
}

fn display(s: &str) {
    println!("{}",s);
}
```
**Rust 编译器实际上只能对 `&v` 形式的引用进行解引用操作**
### DerefMut可变转换
- 要实现 `DerefMut` 必须要先实现 `Deref` 特征：`pub trait DerefMut: Deref`
- `T: DerefMut<Target=U>` 解读：将 `&mut T` 类型通过 `DerefMut` 特征的方法转换为 `&mut U` 类型，对应上例中，就是将 `&mut MyBox<String>` 转换为 `&mut String`

## Rc计数指针
`Rc<T>`是一种引用计数指针类型，用于在多个所有者之间共享数据。以下是`Rc<T>`的常用方法：
1. `Rc::new(value: T) -> Rc<T>`：创建一个新的`Rc<T>`实例，将值`value`包装在其中。
2. `Rc::clone(&self) -> Rc<T>`：克隆`Rc<T>`实例，增加引用计数。这个方法并不会实际复制数据，只是增加了引用计数。
3. `Rc::strong_count(&self) -> usize`：返回`Rc<T>`实例的强引用计数，即当前有多少个`Rc<T>`指向相同的数据。
4. `Rc::weak_count(&self) -> usize`：返回`Rc<T>`实例的弱引用计数，即当前有多少个`Weak<T>`指向相同的数据。
5. `Rc::into_inner(self) -> T`：将`Rc<T>`解包，返回内部的值`T`。如果引用计数大于1，则会抛出运行时错误。
6. `Rc::downgrade(&self) -> Weak<T>`：创建一个指向相同数据的弱引用`Weak<T>`。弱引用不会增加引用计数，可以用于解决循环引用的问题。

## Arc原子计数指针
`Arc<T>`是一种原子引用计数指针类型，用于在多个线程之间共享数据。以下是`Arc<T>`的常用方法：
1. `Arc::new(value: T) -> Arc<T>`：创建一个新的`Arc<T>`实例，将值`value`包装在其中。
2. `Arc::clone(&self) -> Arc<T>`：克隆`Arc<T>`实例，增加引用计数。这个方法并不会实际复制数据，只是增加了引用计数。
3. `Arc::strong_count(&self) -> usize`：返回`Arc<T>`实例的强引用计数，即当前有多少个`Arc<T>`指向相同的数据。
4. `Arc::weak_count(&self) -> usize`：返回`Arc<T>`实例的弱引用计数，即当前有多少个`Weak<T>`指向相同的数据。
5. `Arc::into_raw(self) -> *const T`：将`Arc<T>`转换为裸指针`*const T`，并丢弃`Arc<T>`。需要小心使用，因为裸指针可能导致悬垂引用。
6. `Arc::from_raw(ptr: *const T) -> Arc<T>`：从裸指针`*const T`创建一个`Arc<T>`实例。需要确保裸指针指向有效的数据，并且没有发生资源泄漏。
## Cell常用方法
`Cell<T>`是一种提供内部可变性的类型，它允许你在不可变引用的情况下修改其内部的值。以下是`Cell<T>`的常用方法：
1. `Cell::new(value: T) -> Cell<T>`：创建一个新的`Cell<T>`实例，并将值`value`存储在其中。
2. `get(&self) -> T`：返回`Cell<T>`实例中存储的值。
3. `set(&self, value: T)`：将值`value`存储在`Cell<T>`实例中，即修改内部的值。
4. `replace(&self, value: T) -> T`：将值`value`存储在`Cell<T>`实例中，并返回原来存储的值。这个方法会同时修改内部的值和返回旧值。
5. `into_inner(self) -> T`：解包`Cell<T>`实例，返回内部的值`T`。如果`Cell<T>`实例还有未消费的可变引用，则会在编译时出错。
## Refcell常用方法
在Rust中，`RefCell<T>`是一种提供内部可变性的类型，它允许你在运行时检查借用规则，并在不可变引用的情况下修改其内部的值。以下是`RefCell<T>`的常用方法：
1. `RefCell::new(value: T) -> RefCell<T>`：创建一个新的`RefCell<T>`实例，并将值`value`存储在其中。
2. `borrow(&self) -> Ref<T>`：以不可变引用的方式借用`RefCell<T>`中的值。如果已经存在一个可变引用，则会在运行时产生panic。
3. `borrow_mut(&self) -> RefMut<T>`：以可变引用的方式借用`RefCell<T>`中的值。如果已经存在一个引用（不管是可变引用还是不可变引用），则会在运行时产生panic。
4. `try_borrow(&self) -> Result<Ref<T>, BorrowError>`：以不可变引用的方式尝试借用`RefCell<T>`中的值，返回一个`Result`类型，表示操作是否成功。
5. `try_borrow_mut(&self) -> Result<RefMut<T>, BorrowMutError>`：以可变引用的方式尝试借用`RefCell<T>`中的值，返回一个`Result`类型，表示操作是否成功。
6. `into_inner(self) -> T`：解包`RefCell<T>`实例，返回内部的值`T`。如果`RefCell<T>`实例还有未消费的引用，则会在运行时出错。
7. `get_mut(&mut self) -> &mut T`: 获取对象的可变引用,并独占所有权。
## Cell和RefCell的区别
1. 内部可变性的实现是因为 Rust 使用了 `unsafe`
2. `Cell` 只适用于 `Copy` 类型，用于提供值，而 `RefCell` 用于提供引用
3. `RefCell` 只是将借用规则从编译期推迟到程序运行期，并不能帮你绕过这个规则
4. `Cell` 不会 `panic`，而 `RefCell` 会
