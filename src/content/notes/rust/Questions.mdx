## Marker Traits

在 Rust 中，`std::marker` 模块提供了一组极其特殊的 **Marker Traits（标记 trait）**： 不包含任何方法、关联类型或常量，它们的唯一作用是**作为标签，在编译期向编译器传达类型的核心行为属性**

### `Send`：允许跨线程转移所有权

- **含义**：如果一个类型实现了 `Send`，意味着将该类型的值的所有权从线程 A 转移（Move）到线程 B 是安全的
- **自动实现（Auto Trait）**：绝大多数类型都是自动实现 `Send` 的，只要它的所有成员都实现了 `Send`
- **常见的非 `Send` 类型**：
  - **`Rc<T>`**：因为它的引用计数是非原子操作（非线程安全）。如果多个线程同时增加 `Rc` 的计数，会导致数据竞争（Data Race）
  - **裸指针 `*const T` / `*mut T`**：由于裸指针绕过了 Rust 的安全检查，编译器无法保证其跨线程的安全性，默认非 `Send`

### `Sync`：允许跨线程共享引用

- **含义**：如果一个类型实现了 `Sync`，意味着在多个线程中同时持有该类型的不可变引用（`&T`）是安全的
- **与 `Send` 的关系**：根据定义，**如果 `&T` 是 `Send`，那么 `T` 就是 `Sync`**
- **内部可变性（Internal Mutability）的影响**：
  - `RefCell<T>`、`Cell<T>` **不是** `Sync`。因为它们的内部可变性操作不是原子性的
  - `Mutex<T>`、`RwLock<T>` **是** `Sync`（只要 `T` 是 `Send`）。它们通过底层锁机制保证了多线程并发读写的安全性

### `Copy`：改变赋值语义为“按位复制”

- **含义**：如果一个类型实现了 `Copy`，那么在进行赋值操作（如 `let y = x;`）或函数传参时，会触发**隐式的按位复制（Bitwise Copy）**，而不是所有权的转移（Move）
- **前提条件**：该类型必须已经实现了 `Clone`
- **限制**：任何管理着外部资源（如堆内存、文件句柄）的类型都不能实现 `Copy`（例如 `String`、`Vec<T>`、`Box<T>`），因为按位复制会导致资源被多次双重释放（Double Free）

### `Sized`：编译期已知大小的类型

- **含义**：表示该类型在编译期间具有固定、已知的分配大小
- **默认隐含**：在 Rust 中，所有的泛型参数默认都隐式带有 `T: Sized` 的约束
- **动态大小类型（DST, Dynamic Sized Types）**：例如特征对象 `dyn MyTrait` 或切片 `[u_8]`。它们的大小在编译期无法确定，必须通过指针（如 `&[u_8]` 或 `Box<dyn MyTrait>`）间接使用
- **放宽约束 `?Sized`**：如果你希望泛型可以接受动态大小类型，必须显式写为 `T: ?Sized`（意为“可能是或可能不是 Sized”）

### 什么是 Auto Traits（自动标记）？

在 `std::marker` 中，`Send`、`Sync`、`Unpin` 等属于特殊的 **Auto Traits**。

- **自动推导**：你不需要显式地为你的结构体写 `impl Send for MyStruct {}`。编译器会自动检查：如果 `MyStruct` 里的所有字段都是 `Send` 的，那么 `MyStruct` 自动就是 `Send` 的。
- **主动剥夺（Negative Impl）**：如果你想显式地让一个原本默认是 `Send` 的类型变为非 `Send`，可以使用特殊的语法（需要 unstable 特性，或通过内部组合非 Send 类型实现）：

```Rust
    // 逻辑上剥夺 Send 特征
    impl !Send for MyType {}
```

## Rust中Copy和Clone

### Copy

#### 实现条件

Rust规定，对于自定义类型，只有所有的成员都实现了 Copy trait，这个类型才有资格实现 Copy trait。  
常见的数字类型、bool类型、共享借用指针&，都是具有 `Copy` 属性的类型。而 `Box`、`Vec`、可写借用指针`&mut` 等类型都是不具备 `Copy` 属性的类型。

### Clone

#### 定义

Clone 的全名是 `std::clone::Clone`，它的完整声明是这样的：

```rust
pub trait Clone : Sized {
    fn clone(&self) -> Self;
    fn clone_from(&mut self, source: &Self) {
        *self = source.clone()
    }
}
```

它有两个关联方法，其中 `clone_from` 是有默认实现的，它依赖于 `clone` 方法的实现。`clone` 方法没有默认实现，需要我们手动实现。

### Copy和Clone的区别

1. Copy继承于Clone，因此所有`Copy`类型也一定是`Clone`类型。
2. 从被复制的内容来讲，`Copy`仅只对【栈】内存做【按位复制】，**而不对任何【堆】内存负责**。而，`Clone`需要对复本的**整体有效性**负责，因此像String，Box等类型没有实现`Copy`特征。
3. 从复制的行为上来讲，`Copy`的实现完全由`rustc`来定义,而`Clone`则完全由开发者自己定义。
4. 从调用方式上来讲,`Copy`自动的隐式触发,而`Clone`必须手动调用。

## String 与 &str

官方解释:

- String 是一个被拥有（owned）的在堆上分配的 UTF-8 的字节缓冲区。
- &str 是一个指向分配在某处的 String 的一个固定容量的「视图」。如果切片是在从 String 解引而来的，则通常是指向在堆上，如果是字符串字面值，则指向静态内存。

### &str转为String

```rust
let c =a.to_string(); //方法一
let d =String::from(b) //方法二
let d =a.to_owned();//方法三
```

### String转为&str

```rust
let c =a.as_str(); //方法一
let d =&a[..] //方法二
```

### 什么是dyn?

dyn关键字用于强调相关trait的方法是动态分配的。要以这种方式使用trait，它必须是“对象安全”的。**即实现dyn \_\_ trait的对象大小不确定,在运行时进行动态分发的。**  
栈上的变量必须在编译时确定大小，而动态多态类型的大小在编译时是不确定的。因此，使用`dyn`关键字声明的类型只能通过引用或者智能指针（如`Box<dyn Trait>`、`Rc<dyn Trait>`、`Arc<dyn Trait>`等）来间接引用，从而在堆上分配内存。

### 什么是Sync?

> `Sync`是一个trait（特征），用于标记可以安全地在多个线程之间共享的类型。具体来说，实现了`Sync` trait的类型可以在多个线程中同时访问，而不会引发数据竞争。

要将类型标记为`Sync`，只需为该类型实现`Sync` trait即可,且无需重写任何函数。这通常是由编译器自动完成的，对于绝大多数类型来说，它们都是`Sync`的。但是，如果你有自定义类型，并且需要在多个线程中共享它，你需要确保该类型实现了`Sync` trait。

### 什么是Send？

> `Send`特征用于表示一个类型可以安全地在不同线程之间传递所有权。具有`Send`特征的类型可以跨线程传递，而不会导致数据竞争或其他线程安全问题。

要在类型上实现`Send`特征，需要满足以下两个条件：

1. 类型的所有权可以在线程之间传递，这意味着它是`Sized`的。可以使用`#[derive(Send)]`来自动实现此条件。
2. 类型的所有成员也实现了`Send`特征，或者被标记为`!Send`。如果类型有成员不满足`Send`特征的要求，可以使用`std::marker::PhantomData`或`std::cell::UnsafeCell`等手段来解决。

## 所有权问题

```rust
// 编译成功
fn main() {
    let mut x = 1;
    let y = &mut x;  // 第一次可变借用
    let z = &mut x;  // 第二次可变借用
    println!("{}, {}", x, y);
}

// 编译失败
fn main() {
    let mut x = 1;
    let y = &mut x;
    let z = &mut x;
}
```

为什么成功？

- Rust 的借用检查器有 **非活动借用(non-lexical lifetimes, NLL)** 机制
- 虽然 `y` 在语法上在 `z` 之前声明，但它从未使用过，所以它的作用域在创建 `z` 前就结束了
- 因此，第二个可变借用 `z` 是合法的
