## 分析流程

```bash
uptime   #平均负载（1分钟、5分钟、15分钟）
dmesg | tail    #系统日志
vmstat 1    #虚拟内存统计
mpstat -P ALL 1    #每个CPU 核心的独立使用率
pidstat 1    #查看单进程占用
iostat -xz 1    #磁盘读写次数和繁忙程度
top    #htop或者btop
```

## 分析工具

### sar（System Activity Reporter 系统活动情况报告）

#### 用法说明

```bash
sar [ 选项 ] [ <时间间隔> [ <次数> ] ]
```

- **时间间隔**: 采样的时间间隔（秒）。
- **次数**: 采样的总次数。如果不指定次数，它会一直运行直到用户按 Ctrl+C。

#### 常用选项

**1. CPU 相关**

- **`-u [ ALL ]`**: **最常用**。报告 CPU 利用率。
  - 默认显示：`%user` (用户态), `%system` (内核态), `%iowait` (IO等待), `%idle` (空闲)。
  - 加上 `ALL` 关键字会显示更多字段（如 `%steal`, `%nice` 等）。
- **`-P { <cpu_list> | ALL }`**: 报告**每个 CPU 核心**的统计信息。
  - 例如：`-P ALL` 显示所有核心，`-P 0,1` 只显示核心 0 和 1。
- **`-q`**: 报告**队列长度和平均负载** (Load Average)。
  - 关键指标：`runq-sz` (运行队列长度), `ldavg-1` (1分钟负载)。
- **`-w`**: 报告每秒的**上下文切换** (Context Switches) 和任务创建次数。
- **`-I [ SUM | ALL ]`**: 报告**中断**统计信息。
  - `SUM`: 每秒中断总数。
  - `ALL`: 列出每个具体中断源的统计。

**2. 内存与交换（Memory & Swap）**

- **`-r [ ALL ]`**: 报告**内存利用率**。
  - 关键指标：`kbmemfree` (空闲内存), `kbmemused` (已用内存), `%memused` (内存使用率), `kbbuffers`, `kbcached`。
- **`-S`**: 报告**Swap (交换空间)** 利用率。
- **`-B`**: 报告内存**分页 (Paging)** 统计信息。
  - 涉及 `pgpgin/s` (换入) 和 `pgpgout/s` (换出)。
- **`-W`**: 报告**Swapping (交换活动)** 统计信息。
  - 主要关注 `pswpin/s` 和 `pswpout/s`。
- **`-H`**: 报告 **Hugepages** (大页内存) 的使用情况。

**3. 磁盘与 I/O（Disk & I/O）**

- **`-b`**: 报告 I/O 和传输速率统计。
  - 包括 `tps` (每秒传输次数), `rtps` (读), `wtps` (写), `bread/s`, `bwrt/s`。
- **`-d`**: 报告**块设备 (Block Device)** 的活动状况。
  - **强烈建议搭配 `-p` 使用**，否则设备名会显示为 `dev8-0` 这种形式。
  - 关键指标：`tps`, `rkB/s` (读吞吐), `wkB/s` (写吞吐), `%util` (I/O 利用率/饱和度)。

**4. 网络（Network）**

- **`-n { <keyword> [,...] | ALL }`**: 报告网络统计信息。`keyword` 可以是：
  - `DEV`: 网络接口统计 (流量、包量)。
  - `EDEV`: 网络接口错误统计 (丢包、错误)。
  - `SOCK`: 套接字使用情况 (使用中的 TCP/UDP 等)。
  - `TCP`, `UDP`, `ICMP`, `IP`: 各协议层的统计。
  - `ALL`: 显示所有网络信息。

**5. 文件系统与内核表（Filesystem & Kernel）**

- **`-v`**: 报告内核表状态（如 inode、dentry 和文件句柄的使用情况）。
- **`-F [ MOUNT ]`**: 报告**文件系统**的统计信息。
  - `MOUNT`: 显示挂载点名称。
  - 指标包括文件系统的剩余空间和 inode 使用率。

**6. 电源与频率**

- **`-m { <keyword> [,...] | ALL }`**: 报告电源管理统计信息。
  - 通常用于查看 CPU 频率 (`CPU`)、风扇转速 (`FAN`) 等。

#### 显示与格式化选项

- **`-p`**: **Pretty print**。将设备 ID (如 dev253-0) 转换为易读的设备名 (如 sda, dm-0)。常与 `-d` 配合使用。
- **`-h`, `--human`**: 以人类可读的格式打印（例如自动将数字转换为 k, M, G 单位，而非长串数字）。
- **`--pretty`**: 更加美观的输出格式。
- **`--dec={ 0 | 1 | 2 }`**: 指定输出数值的小数位数。
- **`-t`**: 读取数据文件时，基于数据文件原本的时间戳显示时间，而不是当前系统的 locale 时间。
- **`-z`**: 告诉 sar 省略那些在采样期间没有任何活动的设备的输出（去噪）。
- **`-y`**: 报告 TTY 设备活动。
- **`-V`**: 显示版本信息。

### vmstat（Virtual Meomory Statistics虚拟内存统计）

#### 用法说明

```bash
vmstat [选项] [采样间隔 [采样次数]]
```

- **采样间隔 (delay)**: 以秒为单位刷新数据。
- **采样次数 (count)**: 刷新多少次后退出。如果不指定次数，将持续刷新直到按 `Ctrl+C`。
- **注意**: 如果不指定任何间隔，`vmstat` 只会输出**一行**数据，这行数据反映的是**自系统启动以来的平均值**，而不是当前的实时状态。

#### 常用选项

**1. 内存与显示控制**

- **`-a`, `--active`**: 显示活跃 (active) 和非活跃 (inactive) 内存。
  - 默认情况下，`vmstat` 显示 `buff` (缓冲) 和 `cache` (缓存)。
  - 使用此选项后，这两个字段会被替换为 `inact` (非活跃) 和 `active` (活跃)。
    - **Active**: 最近被使用过的内存，通常不会被回收。
    - **Inactive**: 最近未被使用，是可以被回收用于其他目的的内存候选者。
- **`-f`, `--forks`**: 显示自系统启动以来**创建的进程总数** (forks)。
  - 包括 `fork`, `vfork`, `clone` 系统调用的次数。
  - **用法场景**: 如果这个数字增长极快，说明系统正在频繁创建短命进程，可能导致高系统开销。
- **`-m`, `--slabs`**: 显示内核 **Slab** 分配器的详细信息。
  - 这是内核缓存的详细视图，通常用于深度内核调试。
- **`-s`, `--stats`**: 显示一张**内存和系统事件的摘要表**。
  - 这不会像默认模式那样滚动输出，而是列出各项计数器的累积总值（如总中断数、总上下文切换数、总页换入换出数等）。

**2. 磁盘与分区（Disk & Partition）**

- **`-d`, `--disk`**: 显示**每个磁盘**的详细统计信息。
  - 包括：读/写次数、读/写扇区数、花费在 IO 上的毫秒数。类似于 `iostat` 的简略版。
- **`-D`, `--disk-sum`**: 显示**所有磁盘的汇总**统计信息。
  - 对整个系统的磁盘活动做一个总览。
- **`-p`, `--partition <dev>`**: 显示**指定分区**的读写统计。
  - 必须紧跟设备分区名。
  - 例如：`vmstat -p sda1` (显示 sda1 的读写页数)。

**3. 格式化与输出微调**

- **`-n`, `--one-header`**: 只显示一次表头。
  - 默认情况下，`vmstat` 在输出很多行数据后会再次打印表头。在将输出重定向到日志文件时，使用此选项可以保持数据整洁。
- **`-S`, `--unit <char>`**: 定义显示的单位。
  - `k`: 1000 bytes
  - `K`: 1024 bytes (默认)
  - `m`: 1000000 bytes
  - `M`: 1048576 bytes
  - **注意**: 这只影响内存部分的显示单位。
- **`-w`, `--wide`**: **宽输出模式**。
  - 在内存很大的服务器上，默认输出可能会对齐错乱。使用 `-w` 可以加宽列宽，保证排版整齐。
- **`-t`, `--timestamp`**: 在每一行输出的末尾追加**时间戳**。
  - 非常有用，特别是在记录日志以便后续分析故障发生时间时。
- **`-y`, `--no-first`**: **跳过第一行输出**。
  - **重要**: `vmstat` 的第一行输出通常是“自启动以来的平均值”，往往具有误导性。使用 `-y` 可以直接显示当前的实时数据（需要配合采样间隔使用）。

### pidstat(Process ID Statistics 进程状态统计)

#### 用法说明

```bash
pidstat [ 选项 ] [ <时间间隔> [ <次数> ] ] [ -e <程序> <参数> ]
```

- **时间间隔**: 采样频率（秒）。
- **次数**: 采样多少次后停止。
- **`-e` 特殊用法**: 直接执行某个程序并监控它，直到程序结束。

#### 常用选项

**1. CPU 监控**

- **`-u`**: **(默认选项)** 报告 CPU 使用情况。
  - `%usr`: 用户态 CPU 时间百分比。
  - `%system`: 内核态 CPU 时间百分比。
  - `%guest`: 运行虚拟处理器的时间。
  - `%CPU`: 总 CPU 使用率。
  - `CPU`: 进程正在哪个 CPU 核心上运行。
- **`-I`**: 在 SMP 环境中，报告 CPU 使用率时，将其除以 CPU 总核心数（通常用于衡量单核负载）。_(注：在不同版本中，`-I` 有时也用于显示中断，但在 pidstat 上下文中通常指 IRQ 或 CPU 亲和性相关)_。

**2. 内存监控（Memory）**

- **`-r`**: 报告内存使用情况和**缺页中断 (Page Faults)**。
  - `minflt/s` (**Minor Faults**): 次缺页中断。不需要从磁盘读取，通常是内存分配或共享库加载，速度快。
  - `majflt/s` (**Major Faults**): **主缺页中断**。需要从磁盘加载数据，速度慢，**性能杀手**。
  - `VSZ`: 虚拟内存大小 (KB)。
  - `RSS`: 常驻物理内存大小 (KB)。
  - `%MEM`: 物理内存使用率。

**3. 磁盘 I/O 监控（Disk I/O）**

- **`-d`**: 报告磁盘 I/O 统计信息。**(非常实用，top 命令默认看不到这个)**
  - `kB_rd/s`: 每秒读取的数据量 (KB)。
  - `kB_wr/s`: 每秒写入的数据量 (KB)。
  - `kB_ccwr/s`: 每秒被取消的写入 (Cancelled writes)。通常指数据写入缓存后，在刷入磁盘前被截断或覆盖。

**4. 上下文切换与堆栈（Context Switch & Stack）**

- **`-w`**: 报告**上下文切换** (Context Switching) 活动。
  - `cswch/s` (**Voluntary**): **自愿上下文切换**。进程因为等待资源（如磁盘、网络、锁）而主动让出 CPU。**如果高，说明系统有 I/O 或锁瓶颈。**
  - `nvcswch/s` (**Involuntary**): **非自愿上下文切换**。进程时间片用完，被内核强制剥夺 CPU。**如果高，说明 CPU 争抢严重。**
- **`-s`**: 报告堆栈 (Stack) 使用情况。
  - `StkSize`: 为任务预留的栈空间大小。
  - `StkRef`: 实际引用的栈空间大小。

**5. 线程与内核表**

- **`-t`**: **显示线程 (Threads) 级别的信息**。
  - 默认只显示进程。加上 `-t` 后，会展开显示进程下的所有线程 (TID)。对于调试多线程程序（如 Java, C++ 服务）至关重要。
- **`-v`**: 报告内核表统计（如 inode 表相关）。
- **`-R`**: 报告实时优先级和调度策略信息。

### strace（System Call Tracer 系统调用追踪）

#### 用法说明

```bash
# 模式 A: 启动并追踪一个新命令
strace [选项] <命令> [参数]

# 模式 B: 追踪一个正在运行的进程 (Attach)
strace [选项] -p <PID>
```

#### 常用选项

**1. 进程管理与多线程**

- **`-p <PID>`**: Attach（附着）到一个正在运行的进程进行追踪。
  - 支持同时追踪多个：`-p 1234,5678`。
- **`-f`**: **(必用选项)** 跟踪**子进程**和**线程**。
  - **关键点**: Linux 下线程是通过 `clone` 实现的。如果不加 `-f`，你只能看到主线程在干嘛，对于多线程程序（如 C++ 服务、ROS 节点、Java 应用）几乎没用。**调试多线程程序必加！**
- **`-u <username>`**: 以指定用户的身份运行被追踪的命令。

**2. 过滤与筛选（`-e` 表达式）**

`strace` 默认输出太多，使用过滤可以精准定位。格式为 `-e trace=[set]`。

- **`-e trace=file`**: 追踪所有与文件操作有关的调用 (`open`, `stat`, `chmod`, `unlink`...)。
- **`-e trace=process`**: 追踪进程管理相关 (`fork`, `exec`, `exit`, `wait`...)。
- **`-e trace=network`**: 追踪网络相关 (`socket`, `bind`, `connect`, `accept`, `sendto`, `recvfrom`...)。
- **`-e trace=signal`**: 追踪信号相关。
- **`-e trace=desc`**: 追踪文件描述符读写 (`read`, `write`, `select`, `poll`, `lseek`...)。
- **`-e trace=open,close,read,write`**: 自定义组合。
- **`-e status=failed`**: 只追踪**失败**的系统调用 (用来找 Error，如 `ENOENT`)。
- **`-e status=all`**: 追踪所有系统调用。

**3. 输出格式与内容控制**

- **`-o <filename>`**: 将输出写入**文件**，而不是标准错误输出 (stderr)。
  - 建议始终使用此选项，方便后续用 `vim` 或 `grep` 分析。
- **`-s <size>`**: 指定输出字符串的最大长度 (默认为 32)。
  - **强烈建议设大**（如 `-s 1024`）。默认长度太短，导致文件路径、SQL 语句或网络包内容被截断显示为 `...`，看不全。
- **`-y`**: 解码文件描述符 (FD)。
  - 不显示 `read(3, ...)`，而是显示 `read(3</etc/passwd>, ...)`，让你一眼看出操作的是哪个文件或 socket。
- **`-x` / `-xx`**: 以十六进制形式显示非 ASCII 字符串（查看二进制数据时有用）。

**4. 时间与统计（Profiling）**

- **`-t`**: 在每行开头显示时间（秒）。
- **`-tt`**: 显示微秒级时间。
- **`-ttt`**: 显示微秒级时间戳（Unix epoch），方便脚本解析。
- **`-T`**: 显示每个系统调用**耗费的时间**（在该行末尾显示 `<0.000123>`）。
  - **排查“哪个操作慢/卡顿”时的神器。**
- **`-c`**: **统计模式 (Summary)**。
  - **不输出**每一条具体的日志，而是在程序结束后，打印一张**报表**，列出每个系统调用的调用次数、错误次数、总耗时、平均耗时。

### perf（Performance Counters for Linux 性能分析工具）

#### 用法说明

```bash
 perf [--version] [--help] [OPTIONS] COMMAND [ARGS]
```

`perf` 主要有三个维度的工作方式：

1. **计数 (Counting)**: 统计发生了多少次事件（如 `perf stat`）。准确，无损耗。
2. **采样 (Sampling)**: 每隔一段时间看一眼 CPU 在执行哪行代码（如 `perf record`）。有微小损耗，用于画火焰图或定位热点。
3. **追踪 (Tracing)**: 配合内核 Tracepoints 追踪特定事件（如调度、IO）。

#### 常用选项

**1. 核心五大命令**

这五个命令涵盖了 90% 的性能分析场景，是必须掌握的基础。

- **`list`** (查看支持的指标)
  - **作用**：列出当前系统支持的所有性能事件。
  - **用法**：
    - `perf list`：列出所有支持的事件（CPU周期、缓存未命中、系统调用等）。
    - `perf list sw`：只列出软件事件（如缺页中断）。
    - `perf list hw`：只列出硬件事件（如 CPU 指令数）。
- **`top`** (实时观测)
  - **作用**：类似 Linux 的 `top` 命令，但是它按**函数热度**排序，实时显示当前系统中占用 CPU 最多的函数。
  - **用法**：
    - `perf top`：监控全系统。
    - `perf top -p <PID>`：只监控指定进程。
    - `perf top -g`：开启调用图（Call Graph），显示谁调用了谁。
- **`stat`** (概览统计)
  - **作用**：运行一个程序（或监控一个进程），结束后输出一份总体的硬件指标报告（IPC、指令数、缓存未命中率等）。
  - **用法**：
    - `perf stat ls`：统计 `ls` 命令的执行性能。
    - `perf stat -p <PID> -d`：统计正在运行的进程，`-d` 显示更详细的缓存数据。
- **`record`** (录制数据)
  - **作用**：以指定的频率采样系统状态，并将数据保存到 `perf.data` 文件中。这是离线分析的第一步。
  - **用法**：
    - `perf record -a -g sleep 10`：录制全系统 10 秒，包含调用栈（`-g`）。
    - `perf record -F 99 -p <PID> -g`：以 99Hz 的频率录制指定进程。
- **`report`** (分析报告)
  - **作用**：读取 `perf record` 生成的 `perf.data` 文件，并展示分析结果（通常是 TUI 界面）。
  - **用法**：
    - `perf report`：打开当前目录下的 `perf.data`。
    - `perf report -i mylog.data`：打开指定文件。

**2. 深入代码级分析**

- **`annotate`** (汇编级分析)
  - **作用**：读取 `perf.data`，直接将性能数据映射到**源代码或汇编代码**上。
  - **用法**：`perf annotate -s <函数名>`
  - **场景**：你已经知道 `my_function` 占用了 50% CPU，你想知道具体是哪一行代码（甚至哪条汇编指令）在慢。
- **`script`** (导出数据)
  - **作用**：将 `perf.data` 转储为可读的文本流。
  - **用法**：`perf script -i <data文件名>`
  - **场景**：用于生成**火焰图**（FlameGraph），或者用 Python/Perl 脚本进行自定义数据处理。

**3. 专项分析工具**

- **`mem`** (内存访问分析)
  - **作用**：专门分析内存访问模式，定位导致 Cache Miss 的代码行。
  - **场景**：程序 IPC 很低，怀疑是内存带宽瓶颈。
- **`c2c`** (Cache-to-Cache 共享分析)
  - **作用**：检测**伪共享 (False Sharing)**。
  - **场景**：多线程程序在多核 CPU 上跑不快，怀疑是多个线程频繁争抢同一条缓存行。
- **`sched`** (调度器分析)
  - **作用**：追踪进程调度延迟、上下文切换。
  - **场景**：程序经常卡顿，怀疑是调度器没有及时分配 CPU，或者被其他高优先级进程抢占。
- **`lock`** (锁竞争分析)
  - **作用**：分析内核锁或用户态锁的争用情况。
  - **场景**：多线程程序 CPU 占用不高，但吞吐量上不去，怀疑死锁或锁等待严重。
- **`trace`** (系统调用追踪)
  - **作用**：深受 `strace` 启发的工具，但开销比 `strace` 小得多。
  - **场景**：需要追踪系统调用，但不能忍受 `strace` 带来的巨大性能损耗。
- **`kmem`** (内核内存)
  - **作用**：追踪内核内存分配（Slab 分配器）。
  - **场景**：怀疑内核存在内存泄漏或碎片化严重。
